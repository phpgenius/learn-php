A Complete Authentication System

Registration, login, remember-me, password reset and session hardening — built the way it has to be built.

Free Levels 5–8 12–16 hours Advanced
Why this project

Authentication is the single most commonly botched feature in PHP applications. Getting it right once, by hand, is worth more than any tutorial.

The brief

Build a full authentication system: registration with email verification, login, logout, remember-me cookies, and a password reset flow with expiring tokens.

Passwords are hashed with password_hash() and verified with password_verify(). Session IDs are regenerated on login. Every state-changing request carries a CSRF token.

The reset flow is the hard part: tokens must be single-use, expiring, and stored hashed — never in plaintext in the database.

Requirements

  • password_hash($pw, PASSWORD_DEFAULT) — never md5, sha1 or a hand-rolled hash
  • password_verify() for login, with a constant-time comparison
  • session_regenerate_id(true) immediately after a successful login
  • Session cookie flags: HttpOnly, Secure, SameSite=Lax
  • CSRF token on every POST form, verified before any state change
  • Reset tokens: 32 random bytes, stored hashed, single-use, 1-hour expiry
  • Login rate limiting per email and per IP
  • Generic error messages — never reveal whether an email exists
  • Remember-me token rotated on every use, stored hashed

Starter code

A skeleton to build from — not a solution. Read it, then extend it.

<?php
declare(strict_types=1);

// ---- Registration: hash, never store the password ----
$hash = password_hash($password, PASSWORD_DEFAULT);

$stmt = $pdo->prepare(
    'INSERT INTO users (email, password_hash, created_at) VALUES (?, ?, NOW())'
);
$stmt->execute([$email, $hash]);

// ---- Login: verify, then rotate the session id ----
$stmt = $pdo->prepare('SELECT id, password_hash FROM users WHERE email = ?');
$stmt->execute([$email]);
$user = $stmt->fetch();

// Always run a verify, even when the user does not exist, so the
// response time does not leak whether the email is registered.
$dummy = '$2y$12$usesomesillystringfore7hnbRJHxXVLeakoG8K30oukPsA.ztMG';
$ok = password_verify($password, $user['password_hash'] ?? $dummy);

if ($user && $ok) {
    session_regenerate_id(true);   // defeats session fixation
    $_SESSION['uid']  = (int)$user['id'];
    $_SESSION['csrf'] = bin2hex(random_bytes(32));
    header('Location: /dashboard.php', true, 303);
    exit;
}

// Generic message: never say "no such user" or "wrong password".
$error = 'Email or password is incorrect.';

// ---- Password reset: store the token HASHED, never the token ----
$token = bin2hex(random_bytes(32));
$tokenHash = hash('sha256', $token);

$pdo->prepare(
    'INSERT INTO password_resets (user_id, token_hash, expires_at)
     VALUES (?, ?, DATE_ADD(NOW(), INTERVAL 1 HOUR))'
)->execute([$userId, $tokenHash]);

// Only the raw token goes in the email link; the DB holds the hash.
$link = 'https://example.com/reset.php?token=' . $token;

Stretch goals

  • Add TOTP two-factor authentication
  • Add a session list page showing device and last-seen time
  • Add account lockout after 10 failed attempts
  • Add an audit log of every login and password change

Definition of done

  • Register, then inspect the database — the password column is a bcrypt hash
  • Log in and check the session cookie — HttpOnly and SameSite are set
  • Reuse a reset link — the second attempt is refused
  • Wait past the expiry and use the link — it is refused
  • Log in with a wrong password for a real email and a fake email — identical message and similar timing
  • Submit a form without the CSRF token — it is rejected
